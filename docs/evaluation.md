# 強さの測り方

## 対局の形式

- **1席 vs 2席**：測りたいプレイヤー1人と、同じ比較相手2人で対局する。測る側の席は毎局入れ替える（P0→P1→P2→…）。互角なら勝率33.3%。
- 統計：勝率と、互角（1/3）からの z 値。誤差（95%）の目安は 60局 ±12ポイント、150局 ±7、300局 ±5。
  - 60局では、強くなってきたネット同士の差（数ポイント）は見分けられない。最強の世代を決めるような比較は300局で行う。
- ネット側は訪問数を固定する（評価は200回）。時間ではなく訪問数でそろえると、GPUの負荷に左右されない。
- `--rule mix` のときは3ルールを均等に混ぜ、ルールごとの勝率も出す。

## 道具

- 学習中：`train_loop.py --eval-every N --eval-games G --eval-vs ...` で、N世代ごとに自動で評価する（`eval.jsonl`）。
- 単独：`eval_models.py --run <実行> --gen <世代> --vs <相手...> --games 300 [--rule ...]`（`eval_extra.jsonl`）。

## 比較相手（`--vs` / `--eval-vs` の書き方）

| 書き方 | 相手 | 用途 |
|---|---|---|
| `scaffold:200` | 駒価値の足場のMCTS（200回） | 初期の目安。今のネットには8〜9割勝つので、差が出にくい |
| `greedy` / `random` | 1手読みの駒得優先 / ランダム | 何かが壊れていないかの確認 |
| `gen:N` | 同じ実行の世代N | 固定の基準（例：蒸留直後の世代1） |
| `prev` | eval_every 世代前 | 世代ごとの伸び（ただし相手が毎回変わるので推移は追いにくい） |
| `ext:実行名:N` | 別の実行のモデル | 実行をまたいだ比較（例：`ext:p4:51`） |

- **固定の相手**（足場、特定の世代）を使うと、世代ごとの推移を同じ物差しで追える。相手が毎回変わる `prev` だけだと、相性の偏り（ある相手には強いが別の相手には弱い）を見落とす（results.md の p4 世代11）。
- 手作りエンジン（`engine.js`）との対局は未実施（open_questions.md #4）。
