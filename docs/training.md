# 学習

## ループ（`python/scripts/train_loop.py`、同期版）

```
世代 g のモデル
  → 学習：直近のデータ窓から、ステップ数 = 新しい局面数 × train_ratio ÷ バッチ → 世代 g+1 を保存
  → 自己対局 1000局（self_play.md）→ gen{g+1}.npz
  → 価値の過学習チェック（まだ学習に使っていない、今の自己対局のデータで価値を測る）
  → eval_every 世代ごとに評価対局（evaluation.md）
```

- 途中で止めても、最後に保存した世代から再開する。
- **ゲーティングはしない**（KataGo と同じ）。新しい世代を常に採用し、弱くなっていないかは評価で見る。
- 最初のデータ：何もなければ足場の評価器で2000局を作る。`--init 実行名:世代` を指定すると、そのモデルを世代1として、その自己対局を最初のデータにする（別のルールや別の実行から始めるとき）。

## 損失（`python/shogi3ml/train.py`）

| 項目 | 損失 | 重み |
|---|---|---|
| 方策 | 交差エントロピー（MCTSの訪問分布） | 1.0（全力探索の局面だけ） |
| 価値 | 交差エントロピー（下記のソフトラベル） | 1.5 |
| 順位 | 交差エントロピー | 0.3 |
| 次の脱落者 | 交差エントロピー | 0.2 |
| 今後20手の駒の損失 | Huber | 0.2 |
| 終局時の駒価値 | Huber | 0.1 |
| 残り手数 | Huber | 0.1 |
| 短期の価値（6手後・16手後） | 交差エントロピー（ソフトラベル） | 0.5 |

### 価値の教師（報酬）

- ネットの価値は「3人それぞれが最終的に**1位になる**確率」（3つ足して1）。報酬は1位かどうかだけで、2位も3位も0。入玉勝ちも最後の1人の勝ちも同じ1。
- 教師 = `(1 − q_mix) × 勝者の one-hot ＋ q_mix × MCTS 根の価値`（q_mix = 0.5）。
  - 勝者だけを教師にすると、序盤の勝敗の偶然が大きい三人では、対局ごとの結果を丸暗記して過学習した（results.md の p3_first）。MCTS 根の価値を混ぜると教師のばらつきが減る。
- 脱落した人の勝率は0に固定する（マスク）。
- 報酬を「2位にも少し価値を与える」形に変えるのは、ゲームの性格（誰を狙うか）を変えるので、別の実験として行う（open_questions.md #7）。

## 最適化

- SGD（モメンタム0.9、Nesterov）、重み減衰 1e-4、FP16混合精度、バッチ256。
- 学習率：p4 は 0.02 固定。p5c 以降は **0.005**。蒸留直後の数世代だけ低くする（`--lr-warm 0.002 --lr-warm-gens 3`）。
  - 蒸留の最後の学習率（0.002）から強化学習をいきなり0.02で始めたら、蒸留で覚えたことが崩れた（results.md の p5）。

## データ窓

- 直近 **60万局面**（おおよそ5世代分）から始め、pmix 世代102からは **150万局面**（約12世代分）。ファイルの作成時刻の新しい順に集める。広げた後の20世代は、広げる前より伸びが大きかった（results.md）。
- 1世代の学習ステップ数は、新しく増えた局面数に比例（`train_ratio` 1.0 = 新しい局面1つあたり平均1回使う）。
- KataGo のような「データ総数に応じて自動で広がる窓」ではなく、手で広げている。

## 蒸留（`python/scripts/pretrain_scaffold.py`）

ネットを別のものの強さまで一気に引き上げる教師あり学習。対局データは5%を対局単位で検証用に分け、学習率はコサインで0.02→0.002に下げる。

1. **足場の対局から**（p4）：足場のMCTSで3万局を作り、その訪問分布と勝敗を教師にする。自己対局の強化学習だけでは足場に追いつけなかったため（results.md）。
2. **別の実行の自己対局データから**（`--from-run p4 --from-gens 41-51`）：大きいネットへの移し替え。
3. **先生ネットの出力から**（`--teacher p4:51`、p5c）：教師を、実際の勝敗ではなく先生ネットの出力にする。
   - 方策：全力探索の局面は訪問分布、それ以外は先生の方策。
   - 価値：先生の価値と MCTS 根の価値を半分ずつ（`--v-mix 0.5`）。
   - 補助：先生の各補助ヘッドの出力。
   - 同じ局面には毎回同じ答えが返るので、何周しても勝敗の丸暗記が起きない。勝敗を教師にした8周の蒸留（p5b）は価値が過学習したが、こちらは検証の成績が最良になり、蒸留したネットが先生を超えた。

## ルールを混ぜた学習（`--rule mix`）

- 3つのルールの対局を均等に混ぜて、1つのネットで学ぶ。ルールはネットの入力（ai_architecture.md）。
- 評価も3ルールを混ぜ、ルールごとの勝率を記録する。

## 過去の世代を混ぜた自己対局（`--past-prob`）

- 三人では「誰を狙うか」の流行が世代ごとに巡回し、過去の世代の狙い方に巻き込まれると弱いことがある（results.md の「世代41の赤狙い」）。KataGo は自己対局だけだが、OpenAI Five や AlphaStar のように過去の自分とも対戦させる。
- 設定（pmix 世代62〜）：自己対局の25%で、半分は「現世代2＋過去1」、半分は「現世代1＋過去2」。席は対局ごとにランダム。過去の世代の候補は `--past-start 21 --past-every 10 --past-max 6`、1世代で使うのは1つ（`--past-per-gen 1`、候補を順番に）。
- **学習データは現世代の手番の局面だけ**。過去の世代の手を方策の手本にしない。勝敗はそのまま使う。
- ログに、混ぜた対局での現世代の勝率（1体のとき・2体のとき）を出す。
- 1世代で使う過去の世代を増やすと、推論がモデルごとに分かれて遅くなる（5つ同時で約3倍）。

## 監視

- `log.txt`：各損失、自己対局の平均手数・席ごとの勝ち数・終局の種類、1秒あたりの推論数、評価結果。
- `value_check.jsonl`：未学習データでの価値の損失と正解率（全体・60手未満）。学習データでの正解率と大きく離れたら過学習。
