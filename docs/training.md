# 学習

## ループ

最初は同期版で作る（GPUが1枚のため）。

```
世代 g のモデル
  → 自己対局 N 局（例：500局）
  → 学習 M ステップ（直近のデータ窓から）
  → ONNX 書き出し → 世代 g+1
  → 数世代ごとに評価対局（evaluation.md）
```

- 自己対局と学習の比率は、KataGo の推奨（自己対局側に学習の数倍〜数十倍の計算を割く）を目安に、実測して決める。
- ボトルネックが分かったら非同期に移行する（自己対局と学習を別プロセスで並行、GPUを共有）。
- **ゲーティングはしない**（KataGo と同じ）。新しい世代を常に採用し、弱くなっていないかは評価対局で監視する。

## 損失

| 項目 | 損失 | 重み（初期値） | 備考 |
|---|---|---|---|
| 方策 | 交差エントロピー（MCTSの訪問分布） | 1.0 | 全力探索の局面だけ |
| 価値（勝者） | 交差エントロピー（勝者の one-hot） | 1.5 | |
| 順位 | 交差エントロピー | 0.3 | |
| 次の脱落者 | 交差エントロピー | 0.2 | |
| 今後の駒の損失 | Huber | 0.2 | |
| 終局時の駒価値 | Huber | 0.1 | |
| 残り手数 | Huber | 0.1 | |
| 短期の価値 | 交差エントロピー（ソフトラベル） | 0.5 | |
| 次の人の方策 | 交差エントロピー | 0.15 | 入れる場合 |
| L2正則化 | | 3e-5 | |

重みは初期値。学習が安定してから調整する。

## 最適化

- SGD（モメンタム0.9）、学習率は 0.02 前後から、FP16混合精度。バッチ256〜512。
- 学習率は、データ量の増加に合わせて段階的に下げる。

## データ窓（リプレイバッファ）

- KataGo 式の**増えていく窓**：窓の大きさ = データ総数に応じて増やす（初期は小さく、古いデータがすぐ抜ける。データが増えたら窓も広げる）。
- 初期値：最新 25万局面から始め、総数の平方根に比例して広げる（具体式は実装時に決める）。
- 1局面あたり平均4回程度使われるように、学習ステップ数を自己対局の量に合わせる。

## モデル管理

- `runs/<run名>/models/` に世代ごとの `.pt`（学習再開用）と `.onnx`（推論用）を保存する。
- 各世代に、学習に使ったデータ範囲、損失、評価結果を記録する（`models/index.jsonl`）。
- 実験の設定は `runs/<run名>/config.toml` に1つにまとめ、コードの既定値に頼らない（再現のため）。

## 監視

- TensorBoard（または CSV）に次を記録する：各損失、方策のエントロピー、価値の予測の較正（予測勝率と実際の勝率）、自己対局の平均手数・終局の種類の割合・席ごとの勝率、1秒あたりの推論数。
- 自己対局の**500手制限での終局の割合**は、学習が進んでいるかの早い目安になる（決着をつけられるようになれば下がるはず）。
