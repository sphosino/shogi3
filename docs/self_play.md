# 自己対局とMCTS

## 3人用MCTS

AlphaZero の PUCT を、価値を3つ組にして拡張する（Petosa & Balch 2019「Multiplayer AlphaZero」と同じ考え方）。

- 各ノードは、子ごとに訪問数 N、価値の合計 W（**3つ組**）、事前確率 P（ネットの方策）を持つ。
- **選択**：ノードで手番の人を p とすると、子の中から `Q_p + U` が最大のものを選ぶ。
  - `Q_p = W_p / N`（手番の人にとっての平均勝率）
  - `U = c_puct × P × sqrt(ΣN) / (1 + N)`
  - 未訪問の子の Q は FPU（First Play Urgency）で決める：親の Q_p から一定値を引いた値。
- **展開・評価**：葉でネットを呼び、方策と価値（3つ組）を得る。
- **逆伝播**：葉の価値の3つ組を、根までの各ノードにそのまま足す（2人ゲームのような符号反転はしない）。
- **終局ノード**：勝者が1、他は0（脱落者も0）。
- 各プレイヤーが**自分の勝率を最大にする**という前提なので、パラノイドのように「2人に組まれる」と仮定しない。
  - 比較実験として、「根の人以外は、根の人の勝率を下げる手を選ぶ」パラノイド型MCTSも実装できるようにしておく（experiments.md の E5）。

### パスについて

- 手が1つもない局面は、パスを1つの手として扱う（ほぼ起きない）。

## 自己対局の設定

| 項目 | 初期値 | 備考 |
|---|---|---|
| 1手あたりの訪問数 | 全力探索 600 / 高速探索 100 | 下記「プレイアウト数のランダム化」 |
| 全力探索の割合 | 25% | |
| 根のディリクレノイズ | α = 10 / 平均合法手数、重み 0.25 | 全力探索のときだけ |
| 温度 | 序盤30手は訪問数に比例して選ぶ、以降は最多訪問 | 3人なので「手数」は全員の合計 |
| c_puct | 1.5 | 調整対象 |
| 投了 | なし | 3人なので投了の扱いが難しい。当面は最後まで指す |
| 同時に進める対局数 | 256〜512 | 推論をまとめて行うため |

### KataGo 式の効率化

1. **プレイアウト数のランダム化**：大半の手は少ない探索（100回）で速く指し、一部（25%）だけ多く探索（600回）する。**方策の学習には全力探索の手だけを使う**。価値の学習にはすべての局面を使う。同じ計算量で対局数を増やせる。
2. **強制プレイアウトと方策ターゲットの刈り込み**：全力探索のとき、根の各子に `sqrt(2 × P × ΣN)` 回までは強制的に訪問させる。方策の学習ターゲットを作るときは、強制訪問で水増しされた分を差し引く。
3. **短期の価値ターゲット**：対局後に、6手後・16手後の MCTS 根の価値を補助ターゲットとして付ける（ai_architecture.md）。

### 推論のまとめ方

- 1つの自己対局プロセスで数百局を同時に進める。各局が1回ずつ葉まで降りて評価待ちになったら、まとめて1回推論する。
- 同じ対局の中で並列に探索しない（仮想損失なし）。対局数が多いので不要。
- 同じ局面の推論結果は、小さなキャッシュ（ハッシュで引く）で使い回す。

## 学習データ

1局面ごとに次を保存する（シャード単位、圧縮した numpy 形式を想定）。

| 項目 | 内容 |
|---|---|
| 局面 | 入力を再構成できる最小の形（盤81バイト＋持ち駒21＋脱落3＋手番＋手数）。入力チャンネルは学習時に作る |
| 方策ターゲット | 合法手ごとの訪問数（刈り込み後）。疎な形（手の番号, 訪問数） |
| 方策を学習に使うか | 全力探索の手なら1、高速探索なら0 |
| 根の価値 | MCTS 根の価値（3つ組） |
| 勝者 | 0/1/2 |
| 順位 | 3人分 |
| 補助ターゲット | 次の脱落者、今後20手の駒の損失、終局時の駒価値、残り手数、6手後・16手後の根の価値、次の人の訪問分布 |
| メタ情報 | 対局ID、手数、モデルの世代、取り駒ルール、終局の種類（最後の1人/入玉/500手） |

分析用に、**対局ごとの棋譜（全手）と終局情報**も別ファイルに残す（experiments.md のログ要件）。

## 最初の世代（ネットがない状態）

- ネットがない最初は、**一様な方策と、駒価値の差から作った価値**で MCTS を回して対局を作る（ランダムに指すより意味のある対局になり、500手制限で終わる対局を減らせる）。
- 駒価値からの価値：各プレイヤーの駒価値を softmax にかけたもの（温度は調整）。これは最初の数世代だけの足場で、以降は使わない。
- この足場を使うかは open_questions.md で決める（完全にゼロからでも回るかは試す価値がある）。
