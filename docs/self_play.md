# 自己対局とMCTS

## 3人用MCTS

AlphaZero の PUCT を、価値を3つ組にして拡張する（Petosa & Balch 2019「Multiplayer AlphaZero」と同じ考え方）。

- 各ノードは、子ごとに訪問数 N、価値の合計 W（**3つ組**）、事前確率 P（ネットの方策）を持つ。
- **選択**：ノードで手番の人を p とすると、子の中から `Q_p + U` が最大のものを選ぶ。
  - `Q_p = W_p / N`（手番の人にとっての平均勝率）
  - `U = c_puct × P × sqrt(ΣN) / (1 + N)`
  - 未訪問の子の Q は FPU（First Play Urgency）で決める：親の Q_p から一定値を引いた値。
- **展開・評価**：葉でネットを呼び、方策と価値（3つ組）を得る。
- **逆伝播**：葉の価値の3つ組を、根までの各ノードにそのまま足す（2人ゲームのような符号反転はしない）。
- **終局ノード**：勝者が1、他は0（脱落者も0）。
- 各プレイヤーが**自分の勝率を最大にする**という前提なので、パラノイドのように「2人に組まれる」と仮定しない。
  - 比較実験として、「根の人以外は、根の人の勝率を下げる手を選ぶ」パラノイド型MCTSも実装できるようにしておく（experiments.md の E5）。

### パスについて

- 手が1つもない局面は、パスを1つの手として扱う（ほぼ起きない）。

## 自己対局の設定（`shogi3_rs.Driver` の既定値）

| 項目 | 値 | 備考 |
|---|---|---|
| 1手あたりの訪問数 | 全力探索 600 / 高速探索 100 | 下記「プレイアウト数のランダム化」 |
| 全力探索の割合 | 25% | |
| 根のディリクレノイズ | α = 10 / 合法手数、重み 0.25 | 全力探索のときだけ |
| 温度 | 序盤30手は訪問数に比例して選ぶ、以降は最多訪問 | 手数は3人の合計 |
| c_puct / FPU | 1.5 / 親の Q − 0.2 | |
| 投了 | なし | 最後まで指す（500手制限あり） |
| 同時に進める対局数 | 512 | 推論をまとめるため |
| 1世代の対局数 | 1000 | |
| 取り駒ルール | 1つのルール、または `mix`（3ルールを対局ごとに順に） | 対局番号÷3 で選ぶ（評価で席を回す 対局番号%3 と独立にするため） |

評価対局では、全力探索のみ（既定200回）、ノイズなし、序盤8手だけ訪問数に比例して選ぶ（同じ対局ばかりにならないように）。

### KataGo 式の効率化

1. **プレイアウト数のランダム化**（実装済み）：大半の手は少ない探索（100回）で速く指し、一部（25%）だけ多く探索（600回）する。**方策の学習には全力探索の手だけを使う**。価値の学習にはすべての局面を使う。
2. **短期の価値ターゲット**（実装済み）：対局後に、6手後・16手後の MCTS 根の価値を補助ターゲットとして付ける。
3. 強制プレイアウトと方策ターゲットの刈り込み（未実装）。

### 推論のまとめ方

- 1つの Driver で512局を同時に進める。各局が1回ずつ葉まで降りて評価待ちになったら、まとめて1回推論する。同じ対局の中で並列に探索しない（仮想損失なし）。
- 推論結果のキャッシュはない。

## 学習データ（`runs/<run>/selfplay/genNNNN.npz`、1局面1行）

| 項目 | 内容 |
|---|---|
| states | 局面 109バイト：盤81（駒コード 0=空, 1+持ち主*16+成り*8+駒種）＋持ち駒21（持ち主×駒種7）＋脱落3＋手番1＋手数2（u16 LE）＋取り駒ルール1（0=全部持ち駒 1=お裾分け 2=消滅あり）。2026-09-29 より前のデータは108バイト（ルールなし＝全部持ち駒） |
| policy_offsets / policy_index / policy_visits | 方策ターゲット。合法手の方策番号と訪問数（疎な形） |
| full | 全力探索の手なら1（方策の学習に使う） |
| root_value | MCTS 根の価値（3つ組） |
| winner / rank | 勝者、3人の順位 |
| next_elim, loss20, final_material, remaining, st6, st16 | 補助ターゲット（ai_architecture.md） |
| game_id | 対局番号 |

対局ごとの要約も同じファイルに入れる：`g_id`、`g_winner`、`g_kind`（0=最後の1人 1=入玉 2=500手）、`g_plies`、`g_rule`、`g_seat_net`、`g_moves`（全手の棋譜。手は `to | from<<7 | 成り<<14`）。

## 最初の世代（ネットがない状態）

- ネットがない最初は、駒価値から作った足場の評価器（`engine-rs/mcts` の `MaterialEval`）で MCTS を回して対局を作る。最初の数世代だけ使い、以降は使わない。
  - **価値**：生存者の駒価値の softmax（温度600）。ただし、手番の人が誰かの玉を取れる局面では、その玉取りを指した後の局面で評価する（放置された玉は取られる、を1回の評価で織り込む）。
  - **事前確率**：玉を取る手を大きく（重み+50）、駒を取る手は取る駒の価値に応じて（+駒価値/100）、成る手を少し（+1）高くする。
- 当初は「一様な事前確率」の予定だったが、一様だと合法手約60手 × 相手の応手約60手で、2手先の玉取りにすら探索が届かず、ランダム相手にも勝てなかった（400回探索で勝率38%、30局中19局で自分の玉を取られた）。上の足場にすると、ランダム相手に100%、1手読みの駒得優先に82%（100回）〜95%（1600回）になった（フェーズ2の計測）。
