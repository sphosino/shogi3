# 研究計画

## 目的

1. 三人将棋を、ルールと勝敗だけを与えた自己対局学習で強くする。
2. 学習したAIを使って、三人ゲームで何が起きているか（席の有利不利、戦力差と勝率の関係、誰が誰を狙うか）を調べる。

「強いAIを作る」と「ゲームの構造を調べる」の両方が目的。前者ができないと後者の結論は信用できないので、まず強さを優先する。

## 研究の問い

- **Q1 学習は成立するか**：3人・9×9・持ち駒ありの将棋で、自己対局からの学習が手作りエンジンを超えるか。
- **Q2 席の有利不利**：3つの席（下から攻める青、上から攻める赤、右から攻める緑）に構造的な有利不利はあるか。強いプレイヤー同士になると、表面上の勝率差は消えるのか、別の形で現れるのか。
  - 手作りエンジン同士の対局では、大半の実験で緑の勝ち数が最多だった（例：396局で緑164勝＝41%、132局で緑56〜71勝＝42〜54%。互角なら33%）。ただし赤が最多の回もあった（132局で赤46勝・緑43勝など）。
- **Q3 戦力差と勝率**：戦力（駒価値）の偏りは、そのまま不利になるのか。「弱いと狙われにくい」効果で相殺されるのか。
- **Q4 標的の選択**：1位のプレイヤーは狙われやすいか。誰が誰の駒を取るかは、戦力比でどう変わるか。
- **Q5 探索方式**：3人の勝率を3つ組で扱うMCTSは、パラノイド型（自分以外を1つの敵とみなす）より強いか。

## 仮説

- **H1**：戦力差が大きいほど、直接の戦闘能力の面では不利になる。
- **H2**：ただし三人では、戦力が低いと脅威とみなされにくく、その不利が部分的または完全に相殺される。
- **H3**：そのため、戦力差と勝率の関係は単調ではない可能性がある（中程度の劣勢はそれほど不利でなく、大きな劣勢で急に不利になる、など）。
- **H4**：席の有利不利は、プレイヤーが強くなるほど勝率の差としては小さくなる（有利な席が警戒されるため）。ただし、価値ネットの評価（その席から見た勝率の予測）には残る。

仮説は検証対象であり、学習の設計には入れない（戦力比などを人手で特徴量として与えない）。

## フェーズと完了条件

| フェーズ | 内容 | 完了条件 |
|---|---|---|
| 0. 設計 | この設計書一式 | 未確定事項（open_questions.md）の必須項目が決まっている |
| 1. ルールエンジン | Rustでルールを実装し、JS実装と照合 | 照合テスト（指し手生成・指す/戻す・終局判定）が全局面で一致。指し手生成の速度を計測済み |
| 2. MCTSの骨組み | ネットなし（一様な方策・ランダムプレイアウトまたは駒得の価値）でMCTS自己対局 | ランダムな指し手に対して明確に勝ち越す。1局あたりの時間を計測済み |
| 3. 学習ループ | ネット・学習・ONNX書き出し・推論を一巡させる | 小規模（数千局）で、世代が進むと前の世代に勝ち越す |
| 4. 本格学習 | 自己対局と学習を継続的に回す | 手作りエンジン（中級2秒）に1席 vs 2席で33%超、次に50%超 |
| 5. 分析 | experiments.md の実験 | 各問いについて、統計的な根拠つきの結果が出ている |

フェーズ4の途中でも、フェーズ5の分析用ログは最初から残す（後から取り直すと自己対局をやり直すことになるため）。

## やらないこと（当面）

- 取り駒ルール「お裾分け」「消滅あり」への対応（フェーズ4で「常に持ち駒」が強くなってから）。
- 共闘モード（人間1人をCPU2人が狙う設定）への対応。
- ブラウザで動かすこと。動作環境は、ローカルで十分強くなってから決める。
